# chinalaw-checking 输出模板

不同核对场景对应不同输出形态。下面列出典型模板，agent 选择最贴近用户
意图的形态。所有模板都遵循 [`SKILL.md`](../SKILL.md) §"输出契约"字段集。

注意：普通“依据某条得出某结论”不是原文引用；只有显式引号 / 原文 / 条文 /
摘录 / 规定如下才做文本比对。项目级 AI 工作流审计优先看 grounding 状态。

---

## 模板 A：单条核对（备忘录里某一条引用）

```text
## 核对结果：民法典 第五百二十四条

| 字段 | 值 |
|------|-----|
| 原引用 | 《民法典》第524条 |
| 归一化 | flk-civil-code-2020 / 第524条 |
| DB 命中 | ✅ article#... |
| 文本比对 | exact |
| 状态 | current |
| 时间效力 | 适用（争议时点 2024-01-15） |
| source_url | https://flk.npc.gov.cn/... |
| source_checked_at | 2026-04-19T10:23:00+08:00 |
| 不确定性 | none |

✅ 引用准确，可直接采用。
```

适用：单条 ad-hoc 核对。

## 模板 B：批量核对汇总（合同 / 起诉状里多条引用）

```text
## 核对结果汇总

共核对 12 条引用：8 通过 / 2 wording drift / 1 status 变化 / 1 hard miss。

### 🟢 通过（8）
- 民法典 524 / 525 / 533 / 584 ：exact，current
- 公司法 16 / 32 ：exact，current
- 合同编通则解释 4 / 27 ：exact，current

### 🟡 文本漂移（2）—— 建议人工复核
- **民法典 510**：原文"按照合同有关条款"，AI 写"按照合同条款"——cosmetic_drift
- **公司法 22**：AI 把第二款误植到第一款——structural_mismatch

### 🟠 状态变化（1）
- **合同法 113**（已废止）：自 2021-01-01 起被民法典 584 替代。
  当前材料事实时点 2022-06，应改引民法典 584。

### 🔴 找不到（1）
- **AI 引"民法典 1099-1 条"**：DB 无此条；插入条款检索（`第1099条之1`）
  亦未命中。多源 fetch 已尝试均失败。**疑似 AI 编造**，建议删除。

### 行动建议
1. 把民法典 510、公司法 22 的引用文本对照原文重写
2. 把合同法 113 改为民法典 584
3. 删除民法典 1099-1 引用，或要求用户提供原始来源
```

适用：合同审查 / 起诉状 / 长备忘录。

## 模板 C：时间效力专项（跨期事实）

```text
## 核对结果：时间效力专项

事实时点：2020-08-15（合同签订）
争议焦点：违约责任

### 引用 1：合同法 113 条
- DB 命中：✅ article（status=repealed）
- 文本比对：exact
- 时间效力：⚠️ **用户引用属合同法 1999 修正版本**

### `chinalaw applicable --date 2020-08-15 --topic 违约责任`
- primary_law: 合同法 1999（事实时点 2020-08-15 < 2021-01-01 民法典施行日）
- fallback_law: 民法典
- transition_text: "持续性合同关系 / 跨期违约 / 解除等问题须单独审查"
- not_legal_conclusion: true

### 结论
✅ 用户引用与事实时点的 primary_law 一致，可保留；
⚠️ 但若纠纷处理在 2021-01-01 之后起诉，需结合民法典时间效力规则（详见
最高法关于民法典时间效力规定第 X 条）补充审查。
**注意：上述 primary_law 是检索线索，最终适用结论由律师人工判断。**
```

适用：跨期合同 / 持续侵权 / 担保关系切换等场景。

## 模板 D：核对失败（多条 hard miss / hallucination）

```text
## 核对结果：⚠️ 大面积引用失实

共核对 8 条引用：1 通过 / 7 失实。

### 🔴 失实（7）
| 引用 | 失实类型 | 说明 |
|------|---------|------|
| 《商法典》第 33 条 | hard_miss | **中国无《商法典》**，疑似与公司法或合伙企业法混淆 |
| 民法典 第 1834 条 | hard_miss | 民法典共 1260 条，无 1834 条 |
| 公司法 第 256 条 | hard_miss | 公司法共 218 条（2018 修正）/ 266 条（2023 修订） |
| 合同法解释 第 12 条 | hard_miss | 通称"合通解释"或"合同编通则解释"；AI 写法不规范，且条号错误 |
| 民事诉讼法 第 156 条 | hallucination | DB 命中但文本完全不符——AI 自行编造 |
| 担保法 第 17 条（已废止） | status_repealed | 已被民法典担保部分替代 |
| 公司法 第 32 条 第三款 | structural_mismatch | 公司法 32 条只有两款，AI 编造第三款 |

### 🟢 通过（1）
- 民法典 524：exact、current

### 行动建议
**整份材料引用质量不可信，建议要求用户提供原始来源或重新生成**。

仅保留民法典 524 一条引用作为基础；其余 7 条不能继续使用。
```

适用：纯 AI 生成草稿，质量未知。

## 模板 E：项目级 grounding 审计

```text
## Grounding 审计结果

快照：.chinalaw/snapshots/latest.jsonl
快照记录：18
引用：6 条

### verified（4）
- 民法典 143 → E0003 (`article`)
- 民法典 585 → E0007 (`articles`)

### retrieved_only（1）
- 民法典 584 → E0012 (`search`)：只搜到候选，未 article 精确核验。

### ungrounded（1）
- 劳动合同法 47 → 最终报告引用了该条，但本项目快照中没有任何对应检索记录。

### 处理建议
1. 对 retrieved_only 项执行 `chinalaw article 民法典 584 --format card` 后重跑审计。
2. 对 ungrounded 项补检索；如果补不到，最终报告必须标注依据缺失或删除该结论。
```

适用：审查 AI 最终报告是否有可追溯检索依据链。

## 模板使用提示

- agent 不必死板套用某一种模板；可视情况组合（如先按 B 出汇总，再对失实条
  按 A 详细展开）
- **失实 / 不确定不得隐藏**：哪怕只为讨好用户也不能"挑通过的展示"
- source_url 与 source_checked_at 在所有模板中必须显示，让 reviewer 能跳转
  原文复核
- 跨期场景必须显示 `not_legal_conclusion: true`，提醒 reviewer 这只是线索
