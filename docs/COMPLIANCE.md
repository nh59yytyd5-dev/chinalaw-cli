# 合规与数据使用边界

> 本项目是面向 AI agent 的本地法律规范检索内核。它会从公开政府站点
> （`flk.npc.gov.cn` / `gongbao.court.gov.cn` / `spp.gov.cn` 等）按需读取
> 法规与司法文件文本，并落到本机 SQLite。本文界定了哪些抓取行为在
> 项目范围内、哪些被明确排除，以及使用者应当遵守的红线。

## 1. 数据范围

本项目只触达**已公开发布**的国家法律、行政法规、司法解释、最高法 / 最高检
公报与指导性案例等规范文本。这类文本在中国法律体系下属于公有领域：

> 《中华人民共和国著作权法》第 5 条：本法不适用于：（一）法律、法规，
> 国家机关的决议、决定、命令和其他具有立法、行政、司法性质的文件，
> 及其官方正式译文……

法规正文本身不构成著作权客体，对其检索、复制、引用、清洗后转格式
存储，与现行法没有抵触。

## 2. 红线

下列行为不在本项目范围内，**贡献者不得**通过本仓库的代码、测试、文档
或衍生工具实现或鼓励它们：

1. **突破访问控制 / 反爬保护**：站点显式设置的 robots.txt 禁止路径、登录
   后才可见的内容、付费墙、CAPTCHA 绕过、JavaScript 反爬挑战的破解
   （含 WAF JS challenge 的逆向）一律不做。本项目当前对
   `flk.npc.gov.cn` 的反爬挑战行为是**主动识别 + 报错**而非绕过
   （见 `chinalaw.adapters.flk_npc._looks_like_waf_challenge`）。
2. **个人信息抓取**：当事人姓名、身份证号、住址、电话、车牌号、
   银行账户等个人可识别信息（PII）。公报案例 / 裁判文书中的
   "**X 某某**" 类匿名化文本不属于此列。
3. **大流量请求 / DDoS 倾向**：所有实装的 adapter 默认开启请求节流
   （0.2–0.5 秒间隔），节流不允许配置为 0 或负值（见 §3）。批量
   `sync --batch` 也按串行 + 节流执行，不开多线程并发抓取。
4. **整站镜像 / 商业转售**：本项目不收集、不打包、不分发原始 HTML 镜像；
   入库的是清洗后的条款级 JSON，且仅落本机。任何把本工具产出
   作为付费数据库出售的行为不在项目支持范围。
5. **冒充身份**：User-Agent 中保留 chinalaw-cli 标识（见 §4），不允许
   配置成完全冒充浏览器 / 已知爬虫的形式（虽然代码层面不强制阻止，
   但官方源若发函要求停止抓取，使用者应当配合）。

## 3. 节流策略

所有公开站点 adapter（`flk_npc` / `court_gongbao` / `court_main` /
`spp_gov_cn`）实现
共享语义：

- `request_interval` 默认值见各 adapter 模块（`flk_npc` 0.2s，
  `court_gongbao` / `court_main` / `spp_gov_cn` 0.5s）
- 调用方传入 `<= 0` 或低于 100ms 的值会被 clamp 到 **100ms 硬下限**
  （`MIN_REQUEST_INTERVAL = 0.1`），确保任何调用方都无法关闭节流
- 单进程串行：本项目不在 adapter 层引入并发请求；同一 adapter 实例
  内的请求按 `_last_request_at` 严格排队
- 失败重试也走节流：发生 HTTP 错误或反爬挑战时不立即重试，由调用方
  决定是否人工介入

## 4. User-Agent 标识

所有 HTTP 请求统一附带 `chinalaw-cli/<version> (+<repo-url>)` 形态的
标识，让被抓取站点的 access log 能识别我们这个工具并定位维护者。
基础形态：

```
chinalaw-cli/<version> (+https://github.com/chinalaw-cli/chinalaw-cli)
```

部分 adapter（`court_gongbao` / `court_main` / `spp_gov_cn`）在前置带 `Mozilla/5.0
... Chrome/124.0 Safari/537.36` 兼容前缀，原因是 ASP.NET URLScan
等遗留 WAF 在 UA 完全无浏览器特征时会触发误杀。这并不是冒充浏览器
绕过反爬——chinalaw-cli 标识始终存在，可被站点 access log grep 到。

## 5. 上游站点联系方式

如果你是 `flk.npc.gov.cn` / `gongbao.court.gov.cn` / `www.court.gov.cn` /
`spp.gov.cn`
等被抓取站点的运营方，希望本项目调整抓取行为或停止访问，请通过
以下任一渠道联系：

- 在 GitHub 仓库提 issue（待项目正式发布后填入仓库地址）
- 通过 README 中维护者邮箱

我们会在收到反馈后**24 小时内**调整默认节流、暂停 default adapter 或
彻底移除对应 adapter 模块。

## 6. 使用者责任

下载、安装并运行 chinalaw-cli 的个人或组织：

- **不得**把本工具作为大规模商业爬虫的引擎，绕开 §2 列出的红线
- **不得**在云上 / 多机部署本工具同时抓取同一站点（节流是单进程内的，
  不能跨进程协调）
- **应当**在二次分发清洗后法规文本时附带原始 `source_url` 与
  `source_checked_at`（cleaning 层默认会写这两个字段）
- **应当**对 §1 之外的内容（如付费法律数据库、商业 MCP 返回结果、
  非公开内部规范）单独评估其许可与合规边界，不能直接套用本项目的边界

## 7. 项目立场

本项目不替代法律意见，不是法律服务。它把"获取规范文本"这一基础设施
工作做成本机可控、可审计、可关闭的工具，让 AI agent 在本地基于规范
做工作流编排，而不是把合同 / 案件材料发到远程服务。任何合规、伦理
争议优先**保守解决**：能不抓就不抓，能更慢就更慢，能更明确标识自己
就更明确标识。

—— 本文件随 v0.2 系列首次落地。后续 adapter 接入时同步在 §1 / §3 / §5
更新覆盖范围与联系方式。
