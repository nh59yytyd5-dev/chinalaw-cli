# 差异化与商业 MCP 边界

> 本文档回答：在北大法宝、威科、律商等法律科技公司已有数据库、API 或 MCP 能力时，`chinalaw-cli` 为什么仍然值得做。

## 1. 核心结论

`chinalaw-cli` 不做“另一个法律数据库”。

它做的是：

> 面向 AI agent 法律工作流的本地规范来源内核。

商业法律数据库的优势是内容规模、人工编辑、授权合规、商业检索、SaaS / API / MCP 交付。`chinalaw-cli` 不应正面竞争这些能力。

## 2. 不竞争什么

- 不拼法规、案例、文书的总量。
- 不拼商业检索网站体验。
- 不做远程 SaaS / MCP 数据服务。
- 不做替代律师判断的法律问答机器人。
- 不复制案例库和裁判文书库。
- 不优先做 GUI、账号、多租户、企业交付。

## 3. 竞争什么

### Local-first

合同、案件材料、公司制度、客户要求不能默认上传远程服务。项目必须能在本机运行、离线检索、独立备份和审计。

### Agent-first

任何能调 shell 的 agent 都能用：

```bash
chinalaw search 合同效力 --format json
chinalaw article 民法典 第一百四十三条 --format json
chinalaw fetch 民法典 --article 第五百八十五条 --format json
```

重点是 JSON schema、退出码、错误信息、字段稳定性，而不是界面。

### 私域规范融合

商业数据库通常不维护用户自己的制度和项目约束：

- 公司规章制度
- 甲方放款要求
- HR 制度
- 内部合规手册
- 客户 instruction
- 项目特别要求

这些内容对真实 agent 工作流很重要。`chinalaw-cli` 应让它们进入同一检索流程，但必须明确区分效力层级。

### Fetch + Cleaning

上游来源可以很多：国家法律法规数据库、法院网站、国务院网站、商业 MCP、本地 docx、markdown。

项目的关键不是“自己拥有最大数据库”，而是把不同来源清洗成稳定、可追溯、agent 可读取的本地结构。

### 时间效力检索辅助

法律工作经常要问：事实发生在某个时间点，当时应查什么规范？

`chinalaw-cli` 不应直接替代律师判断，但应帮助 agent：

- 识别现行法和历史法的差异。
- 找到施行 / 废止时间。
- 根据关系线索 fetch 旧法。
- 返回过渡规则、warning 和来源。

## 4. 与商业 MCP 的关系

商业 MCP 更像：

> 远程权威法律数据服务。

`chinalaw-cli` 更像：

> 本地规范来源操作层。

合理组合方式：

- 商业 MCP 作为上游 adapter。
- `chinalaw-cli` 做本地缓存、清洗、hash、版本快照。
- 用户把外部检索结果沉淀为本地规范、规范包或 workflow 资产。
- agent 先查本地稳定资产，缺口再请求上游。

## 5. 规范包的短期边界

规范包有价值，但近期不做复杂包生态。

当前定位：

- 标签
- 收藏
- 问题域清单
- agent 工作流提示

暂不做：

- 远程安装源
- 签名
- 包仓库
- 团队分发
- 复杂冲突判断

## 6. 实现优先级

优先：

- fetch 稳定性
- cleaning pipeline
- 来源追溯
- 私域规范元数据
- 时间效力检索辅助
- legal research / contract review skill

降低优先级：

- GUI
- 账号系统
- 云端同步
- MCP server 产品化
- 全量数据运营
- 复杂规范包生态

## 7. 判断标准

一个功能值得做，必须至少满足一项：

- 提升 agent grounding。
- 提升来源、状态、版本、hash 的可追溯性。
- 更适合本地私人工作流。
- 更好地区分国家法、准规范、私域规范和事项约束。
- 帮助上游数据进入可复用的本地结构。
