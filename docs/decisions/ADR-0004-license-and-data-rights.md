# ADR-0004: License and data rights — Apache-2.0 code, public-domain data, private-by-default norms

- 状态：Accepted
- 日期：2026-04-26
- 关联：[../../LICENSE](../../LICENSE), [../../NOTICES.md](../../NOTICES.md), [PERSPECTIVE.md](../PERSPECTIVE.md)

## Context

中国法律检索这个领域有几条不能踩的红线：
1. 法律法规本身在公有领域（无版权），但**编排版式 / 校对**可能有版权（个别商业数据库主张）。
2. 司法解释、判决书等同样在公有领域，但部分汇编出版物有汇编作品权。
3. 用户的私域规范（合规手册、风控政策、商业合同模板）属于客户内部资产，
   不能流出本机、不能上云、不能被项目维护者获取。
4. 项目自身的代码与文档可以开源，但要决定具体的 license 类型。

社区角度，开源中文法律工具的常见模式分两类：
- "AGPL/Copyleft" 偏激进，但会让企业法务、律所等"不能开源源码"的用户用不上。
- "MIT" 极度宽松，但允许下游闭源 fork，可能与"协议层中立"的初衷有张力。

需要选一个清晰的组合，并把"用户数据本地"的承诺写进可被验证的代码。

## Decision

1. **代码 + 文档：Apache-2.0**。
   - 包含明确的专利授权条款，让 agent 工具厂商敢用。
   - 允许 fork、闭源衍生，但要求标记修改 + 保留 NOTICE。
   - `LICENSE`、`NOTICES.md` 已存在，本期不变。

2. **公开法规数据：公有领域 + 来源标注**。
   - 法律法规 / 司法解释本身的文本属公有领域。
   - 我们对编排（条款分块、分类、FTS 索引）不主张版权。
   - 我们**不收录**任何商业数据库的"附加性内容"（裁判要旨综述、专家点评等）。
   - 引用必须保留来源 URL（见 ADR-0003）。

3. **私域规范：默认本地、永不上传**。
   - SQLite DB 是本地单文件（`~/.chinalaw/chinalaw.db`）；CLI 没有任何
     外联调用，除了用户主动调用 `sync --source flk_npc`（且只对公开法规数据源）。
   - **本期严格禁止**任何"匿名遥测"、"使用统计"、"错误上报"。
     如果未来要加，必须默认关闭、文档化、且不传任何用户内容。
   - 早期用户在邀请话术中明确这一条："数据本地，不上传任何东西"。

4. **规范包贡献**：
   - 用户分享给社区的规范包（pack JSON）按 Apache-2.0 默认协议；
     包含私域条款的规范包**不应提交到主仓**。
   - 公开仓库暂不内置规范包数据；未来如恢复 `data/packs/`，只放公开示范包，
     并标注 `maintainer: chinalaw demo` 等。

5. **第三方数据源**：
   - flk_npc 是国家法律法规数据库（公开），抓取仅复刻其页面公开输出。
     遵守 robots.txt 与合理速率（默认每页 ≥ 200ms 间隔）。
   - 不实现绕过反爬措施的逻辑。
   - 不集成任何要求登录、付费或合同授权的数据源。

## Consequences

正面：
- Apache-2.0 让法律科技公司、律所、企业法务都能放心引用 / 商用。
- "数据本地" 承诺写进了**架构**而不是文案，逐项可以审计：没有 HTTP client
  指向我们自己的 server、没有 telemetry SDK、私域规范的 import 路径不出本地。
- 公有领域数据 + 编排不主张版权，使得 fork 项目可以无障碍地复用整个数据集。

负面：
- 不能用"匿名使用统计"快速判断用户增长，只能靠访谈。
  这与 v0.2 的"5 个真实用户"策略一致，反而是正面约束。
- 商业数据库的"裁判要旨综述、案号 + 律师评注"等增值内容不收录，
  意味着 chinalaw-cli 不会成为"一站式判例平台"。
  这正是中立性的代价——我们做协议层，不做内容运营。

## Alternatives considered

- **AGPL-3.0**：能强制下游开源衍生，但会吓跑大量企业用户与商业 agent 厂商。
  与"协议层希望被广泛复用"的目标相悖。
- **MIT**：比 Apache 更宽松，但缺少专利授权条款，不利于 agent 工具厂商使用。
- **匿名遥测**：哪怕只发 hash，对法律行业用户来说都是不可接受的；
  审计难度大于潜在收益。
- **集成商业数据源**：会把项目卷入版权 / 反爬纠纷，违反"开源中立"。

## Follow-ups

- v0.1.0 release notes 必须重申 license 与数据来源边界。
- 出现以下任一情形时，考虑修订本 ADR：
  - 早期用户中 ≥ 2 人主动要求支持商业数据源接入（带授权许可）；
  - 法律法规版本变更频率提升到本地 SQLite 同步成本难以承担；
  - 出现明确的合规审计需求要本地 read-only 模式（要新增 ADR）。
