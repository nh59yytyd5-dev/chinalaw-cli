# MCP 调用的模型用量与证据沉淀

2026-10-05 离线复算。原始试验与修复见 [真实体验报告](../2026-10-05-real-user-ux.md)，
历次资料入口见 [证据索引](../README.md)。本次统计没有再调用付费模型。

## 已测到什么

39 次 Harness 运行中，32 次完成、5 次启动环境失败、2 次余额不足。会话共记录 219 个
模型步骤，其中 217 次有 provider usage；另 2 次没有用量回报，不能将它们当成计费为零。
561 次 MCP 调用与服务端查询日志逐轮对齐，所有调用均有工具返回记录。

| 用量 | 实测 token |
|---|---:|
| 未缓存输入 `inputTokens` | 1,433,877 |
| 缓存命中输入 `cacheReadTokens` | 5,358,080 |
| 全部输入（以上两项之和） | **6,791,957** |
| 输出 `outputTokens` | **420,215** |
| 输入＋输出 | **7,212,172** |
| 输出内的推理部分 `reasoningTokens` | 295,459 |

缓存命中占全部输入 **78.89%**。推理占输出 **70.31%**，已包含在输出中，不能再次加总。
本机 DeepSeek adapter `@deepseek-ai/dsh-llm-deepseek` 0.1.0-rc.6 的转换为：
`inputTokens = prompt_tokens - cached_tokens`；`outputTokens = completion_tokens`。
Harness 主程序是 0.1.0-rc.8；两者是不同包。四个 usage 字段与之前保存的汇总完全一致。

上述量涵盖整个模型工作流：系统提示、工具定义、任务、历史对话、工具返回、规划和最终
回答等。MCP 服务没有独立的语言模型 token 计费器；访问凭据的调用次数也不是语言模型
token。193 条历史真实用户日志只有工具参数、结果摘要和时延，没有当时模型的 usage，
因此**无法补算那些真实用户会话的精确 token 消耗**。772 次确定性重放不调用语言模型。

32 次完成任务记录了未缓存输入 1,399,415、缓存输入 5,324,800、输出 415,014 token；
余额不足任务在中断前记录了另 34,462、33,280、5,201 token，已纳入总量。
账户余额从 12.78 元变为 -0.14 元，变化 12.92 元；结算延迟明显，这不是逐工具账单，
也不能用即时余额差精确分摊到各轮。不同类型 token 单价不同，总 token 也不是费用。

## 哪些工具带回的信息最多

下面是 **Harness `tool/result` 中文本块的 UTF-8 字节数**，不是 token，也不是 HTTP
线上传输大小。完整保留 JSON 内的文本和格式；外层协议封装不计入这列。另有
`result_content_json_bytes` 记录内容块 JSON 的序列化体积。当前所有结果都是文本块。

| 工具 | 次数 | 返回字节总量 | 占比 | 中位数 / 字节 | P95 / 字节 | 最大 / 字节 |
|---|---:|---:|---:|---:|---:|---:|
| search | 237 | 2,372,715 | 48.89% | 3,983 | 36,911 | 98,463 |
| article | 147 | 1,466,981 | 30.23% | 5,226 | 17,210 | 49,998 |

| 合计 | **561** | **4,853,214** | 100% | — | — | — |

P95 使用 nearest-rank，偶数样本中位数取中间两项平均。计入成功、预期错误和中断前返回，
不能从错误个数直接得到产品失败率。历史时延、Docker 服务端时延、Harness 工具等待时间
保留各自口径，不混为端到端用户等待时间。

四个结果被早期 Harness 的头尾拼接策略裁剪（3 次 search、1 次 article）；本表对它们
记录的是裁剪后的可见文本，而非服务端完整文本。最大 98,463 字节的搜索来自
`dsh-v2-missing-corpus`。全部大响应定位记录见 [summary.json](summary.json)。

工具定义也会占用输入上下文：基线 long-queries 的 6 个 MCP 定义序列化后为 4,124 字节，
最终 scoped-citations 为 5,797 字节。这里比较的是记录到的定义快照，不是每次 API 请求
的实际 wire payload；未使用经验证的 DeepSeek tokenizer，因此不换算成精确 token。

## 如何把用量和调用关联

模型在第 i 步生成的工具调用，其返回通常在第 i+1 步进入模型上下文。
[steps.jsonl](steps.jsonl) 用 `preceding_mcp_results` 指向此前结果的 `call_seq`，
再结合 `run + artifact` 与 [calls.jsonl](calls.jsonl) 联结。156 个后续步骤接收过 MCP
结果，其中 136 个步骤一次接收多个结果；这些步骤的 usage 是整轮的总量。

这种关联只表明调用时序，**不代表已测出该批返回贡献了多少 token**。同一份返回还可能
被后续多轮重复带入，也可能被上下文压缩；规划消息、模型推理和其他上下文同样影响输入。
余额不足的大文档任务最后一步之前已有 5 次 MCP 返回、29,334 字节文本，但这一生成
没有 usage。不得把它们算成零开销，也不能将全流程 token 平均分成 561 份当作单次账单。

服务端按行号单独保留在 [servers.jsonl](servers.jsonl)，没有强行按数组位置与客户端
一一配对：并行调用的到达顺序和默认参数可能不同。两边的逐轮数量已经一致。

相同 prompt 的五组试验能用于定位行为变化，但 v2 开始关闭结果裁剪，早期 profile
快照不完整，而且每个条件只有单次运行；跨版本用量差不能直接解释为代码节省或浪费。
公开 run 数据保留 prompt hash、冻结源码 hash、模型配置、profile 和源日志定位。
没有运行当时源码哈希的记录明确标为事后从冻结目录计算，不伪装成当时已经记录。

## 历史重放也保留逐项证据

[history.jsonl](history.jsonl) 保留 193 条历史调用的匿名参与者、工具、时延、错误和
结果计数；不导出原始查询、姓名或凭据。[replays.jsonl](replays.jsonl) 保留 772 条
重放指标，用 `id` 与历史记录联结，再按 `replay` 比较。

| 同一组 193 次请求 | 返回文本 / 字节 | 搜索零命中 / 78 | 工具错误 |
|---|---:|---:|---:|
| 当前快照＋旧代码 | 2,000,830 | 26 | 5 |
| v1 诊断提示 | 2,028,241 | 26 | 5 |
| v2 | 2,027,760 | 24 | 5 |
| 最终版 | 2,008,637 | 25 | 5 |

最终版与旧代码的总返回体积差为 **+0.39%**，这是确定性重放的文本大小差，不能直接
推成模型费用变化。历史生产记录有 27 个零命中，当前快照旧代码是 26 个，差异来自数据
快照变化。最终版比 v2 多一个零命中，对应 id=1820；原先只有模糊补充的一个命中，数字
完整性修复后不再返回。这个变化及其原始响应一并留存，不能只挑命中增加的结果报告。

## 对下一轮改善的依据

1. **先研究 search 和 article 的返回体积。** 两者贡献 79.12% 的可见返回字节。检查是否
   可减少重复元数据、先给定位信息再按需读正文，并保留法规身份、版本、出处和续读能力。
   本轮只建立基线，尚未据此裁掉任何法律内容或改变默认返回结构。
2. **保留结构，控制分页。** 已证实头尾拼接会混合文件身份和来源，不能用这类裁剪换取
   便宜的输入；之后应比较结构完整的分页方案，并检查任务是否仍能完成。
3. **分别评估模型推理和工具成本。** 当前 high 模式推理占输出七成；较低推理配置是否
   合适需要同任务、同资料、同完整输出配置的质量对照，不能只看 token 降低。
4. **将任务质量和用量一起记录。** 固定数据库、prompt、代码、工具定义、Harness 配置，
   分别记录命中/诊断、引用核验、任务完成情况、模型用量和等待时间；失败与缺失计量保留。

| [provenance.json](provenance.json) | 输入和导出校验值、脚本校验值、数据库与 adapter 指纹 |

所有 `.jsonl` 为一行一个对象；空值和无 usage 步骤表示未知或不存在。总量是已记录
usage 的加总，不为未回报的请求补造用量。模型的 reasoning 文本、提示词、工具参数和
返回正文都留在私有归档，公开数据只导出允许的指标字段。

Node 22.23.2、Python 3，本轮执行入口：

```sh
node scripts/ux_eval/token_analysis.cjs \
  var/ux-deepseek-20261005 /tmp/chinalaw-token-recomputed-v1
node --test scripts/ux_eval/token_analysis.test.cjs
.venv/bin/pytest -q tests/test_ux_evidence.py tests/test_ux_eval.py
```

输出目录必须尚不存在，且在原始输入目录之外；脚本不会覆写原始记录。zstd 拼接帧全部
解码后只累加 `assistant/message.usage`，不重复累加流式片段。7 项 Node 测试及 3 项
Python 测试通过，覆盖分帧、批次关联、缺失用量、脱敏、裁剪标记和归档损坏检测。
公开 8 个指标文件已从原始记录重新生成并核对；Ruff 与空白检查通过。
