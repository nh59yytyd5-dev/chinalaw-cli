# 搜索定位视图：实现与 Docker 验收

第二批 [MCP 用量优化](2026-10-05-mcp-optimization-plan.md) 已实现：HTTP 和 stdio
的 chinalaw_search 增加可选 `view=brief`，默认 full 保持兼容。处理仅发生在已有搜索、
排序、筛选和授权之后，保留所有候选及元数据。条文正文变为最多 240 个 Unicode 码点
的连续原文摘录，明确记录位置、原文长度和是否截断，不使用生成式摘要或头尾拼接。

```json
{"name":"chinalaw_search","arguments":{"query":"保证期间","kind":"article","view":"brief"}}
```

每个条文摘录附 read.tool/arguments 和正文 SHA-256，整次检索附 view.full。短条文
truncated=false 时已经完整展示，按需读取不意味着必须再读一次。文件标题命中保持
原定位元数据，可用 HTTP 既有 document 工具按 ID 读全文。

## 版本与权限边界

- 普通关键词命中来自已存储的 article 记录；搜索 as_of 用于排名和效力标签。读回时
  使用明确 law_id，不擅自将 as_of 传给 article 再选择不同的修订。
- 明确的历史条号命中本来就来自按日期读取的快照，read 保留原日期。text_version
  明示 stored_record/as_of，附正文哈希；法规 ID、条号、来源和全文必须一起核对。
- 私域条款 ID 可能与公开法规相同，不能给出公共优先的模糊读条入口。因此私域条款
  及无法归一的特殊条号用相同条件的 full 搜索恢复，并明确 result_path。该方式可能
  返回多个候选，但不扩大查询范围或权限。正文在两次请求之间变化时须重新定位。
- 新视图不改检索算法、数据、CLI/REST 或默认响应。不是所有日期条件都等于历史正文
  快照，这一现有区别在视图中明确呈现，没有在本任务中改动选法规则。

## 确定性 Docker 实测

同一公开库快照、2 CPU/2 GiB 容器、非 root、只读根文件系统、一次性公开凭据。
冻结旧代码 993fb9b 与新代码分别重放，随后按新响应实际生成并执行恢复请求。

| 检查 | 结果 |
|---|---|
| 旧基线与新默认 | 各 193 次，全部响应完全一致 |
| brief 请求 | 78 次，包括原有的 2 次权限拒绝，错误保持一致 |
| 摘录 | 188 个；其中 45 个截断、143 个已含完整条文 |
| 完整恢复 | 76 次完整搜索 + 188 次逐命中读回，共 264 次；全部核对通过 |
| 真实 MCP 总调用 | **728 次** |
| 78 次搜索返回 | 1,052,337 → **470,415 字节，减少 55.30%** |
| 原 193 次流程只替换搜索视图 | 2,008,637 → **1,426,715 字节，减少 28.97%** |
| 最大单次搜索返回 | 152,992 → 38,647 字节 |
| 模型 token / 费用 | 未测量，无新增模型调用 |

大小均为 MCP 文本块的 UTF-8 字节，包含新摘录说明、版本指纹和恢复入口。收益集中在
长正文：78 次中 10 次变小、2 次不变、66 次因增加定位信息而变大，不能声称每次搜索
都更省。193 次流程比较不含为了验收而额外执行的恢复调用；真实使用中的全文补读
应计入工作流总用量，不能把 55.30% 字节降幅当作净 token 或费用收益。

对每个候选逐字段核对：仅 text 被 excerpt/read/text_version 替代，其他字段与排序
完全一致；摘录确为原文相应位置的切片，读回全文与原正文完全相等，ID、条号和来源
一致。view.full 的实际结果与原完整搜索一致。没有仅靠“调用成功”判定正文正确。
