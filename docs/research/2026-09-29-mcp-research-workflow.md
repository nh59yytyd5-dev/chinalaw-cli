# MCP 法律研究工作流实测

2026-09-29，通过当前会话配置的 chinalaw MCP 原生工具访问甲骨文线上库；没有绕过 MCP 查 SQLite，
没有为测试补库或修改服务。共 81 次调用：35 次 search、6 次 resolve、40 次 article。
原始请求、响应和调用编号见 [trace.jsonl](mcp-research-20260929/trace.jsonl)，问题集见 [cases.json](mcp-research-20260929/cases.json)。

## 用户确认的主流程

用户在本轮明确：模型通常知道候选法规和大致条号，项目不需要学术术语检索。
默认 **记忆给候选 → article 核对原文、身份、版本和来源 → 记忆不准或需补齐依据时才 search**。
记忆允许选择入参，不能作为最终证据；“条号存在”也不意味着条文对题。

因此，下列 8 个直接定位案例和 1 个明确标识的旧号对照是主流程测试。
前面已经进行的 14 个领域关键词探索只保留为辅助检索观察，不以术语空结果作为功能缺陷，
也不据此立项术语表、学术术语搜索或语义检索。

## 一、记忆定位后的直接核验

8 个案例均用候选法规名和条号直接调用 article，全部返回对题原文，无需先 search。
它们是构造的能力样本，不是随机抽样，不代表模型对所有法律问题的记忆准确率。

## 二、旧号对照：有返回不等于核验通过

问题：2026 年订立的仲裁协议应包含哪些事项？使用旧法记忆中的《仲裁法》第16条作为显式干扰对照。

1. C077 直接取现行第16条：返回的是“仲裁机构变更名称、住所、章程……”的登记规则，内容不对题。
2. C078 改用 `仲裁法 仲裁协议 请求仲裁的意思表示` 搜索：现行第27条排第2；第1是较长的组建方案全文，须读内容甄别。
3. C081 精确取现行第27条：包含请求仲裁的意思表示、仲裁事项、选定的仲裁机构，及新增的视为存在仲裁协议情形。
4. C079 带 `as_of=2025-06-01` 取第16条：核对到旧版仲裁协议内容，验证错位来自新旧版本。

MCP 返回的现行版本施行日为 2026-03-01。此对照说明评测应检查“是否发现内容不符并纠正”，
不能只检查 article 是否返回成功。它是人为加入的旧号控制案例，不计为自然记忆失败率。

## 四、仍值得处理的事项

与术语召回无关的实际观察：

- **来源可追溯性**：默认刑法入口优先返回本地维护文本，不能点击官方来源。应核对与官方记录的关联及默认来源选择。
- **版本展示待核**：`通信自由 检查` 同时返回宪法1982年和2018年文本，两者都标 current，且1982年记录是单独 work。
  本测试记录这一现象，未自行改定两者的法律状态。需核对官方记录角色与作品归组。
- **短称可辨识性**：劳动争议解释（一）、（二）等短称都显示为“劳动争议解释”；`resolve 劳动争议解释二`
  给出5个同分候选，现行（二）居首但仍必须读全称、日期并用 ID 取条。没有自动误采用候选。
- **兜底检索噪声**：长篇修改决定或方案可把相距很远的词聚到同一“正文”中；环境、专利、仲裁查询均出现过。
  这影响需要搜索时的审阅成本，但不据此要求建立术语语义检索。

81 次工具调用均有结构化结果，40 次取条均返回正文；其中旧仲裁第16条虽返回成功却不对题，已由内容核验识别。
应持续考察原文相关性、版本/来源、错误记忆纠正和补查成本，而不是“工具没有报错”或“术语搜到了多少”。
