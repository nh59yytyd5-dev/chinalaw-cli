# 剩余 issue（#35 / #34 / #31 / #19）修复方案与 0.7.3 发布

2026-10-13。四个 issue 均已对照代码与线上来源复现，本文件记录根因、修法、不做的部分及确认结果。

## #35 证监会公告正文仅在附件中

**复现**（`csrc/c101954/c7547906`，公告〔2025〕5号）：

- 适配器其实选中并成功读取了附件1《关于修改、废止部分证券期货规范性文件的决定》，但该 PDF 只有“一、对 65 部规范性文件的部分条款予以修改（附件1）二、对 2 部予以废止（附件2）”两项，无“第X条”，于是退回网页 112 字发布语。
- 真正的修改指令与重新公布全文在附件1-1（七百多页，含 65 部规范），因标题不含法规名未被选中。
- 报错来自 `contracts.py` 的通用校验，适配器本有的“附件提取失败”报错路径在 `canonicalize` 之后，永远走不到。
- 附加问题：附件过滤只排除“修订说明 / 起草说明 / 征求意见 / 反馈情况”，漏了“立法说明”，附件2 也被当作正文候选。

**修法**（不涉法律判断）：

1. `canonicalize` 前先判定是否解析出条文；零条文时抛出带线索的错误：列出每个附件的标题与官方 URL，说明哪个已读取但未识别条文结构、哪些因标题不匹配未自动读取（可能含多份文书），提示暂不支持多文书附件自动拆分。仍拒绝导入。
2. 附件过滤补充排除“立法说明”“编制说明”。

**不做**：把附件1-1 拆成 65 份规范各自的修正文本并接入其版本链（见已确认 1）。

## #34 法院网修改决定页附载重新公布的解释

**复现**（`zixun/xiangqing/506981`）：页面依次为新闻通稿、法释〔2026〕13号《修改决定》（“一、将第一条第一项修改为……六、……本决定自2026年7月27日起施行。根据本决定，《……解释》作相应修改……重新公布。”）、附载的修正后解释全文（第一条至第十一条）。解析器只认“第X条”，于是把第三段的条文挂到修改决定的标题和文号下。

**修法**（沿用库内既有做法，不新增法律判断）：库里 flk 的修改决定（如律师法修改决定）一律以单条“正文”保存，从标题到“……重新公布。”为止。court_main 识别“关于修改……的决定”且正文含“根据本决定……重新公布。”时：

1. 决定正文从公告句（“现予公布”）或文号行开始，截至“重新公布。”，去掉新闻通稿；作为单条“正文”保存，标题、文号、施行日期均取自决定本身。
2. 截去附载的修正后全文，不挂在决定名下；fetch 返回的临时 `warnings` 增加 `republished_text_not_imported`，写明附载文书标题（写库前照常剥离）。
3. 未出现“重新公布”句的页面行为不变。

回归测试核对标题、文号、正文同属修改决定，且不含附载解释条文与新闻通稿。

**不做**：把附载的修正后解释作为 2012 年解释的新版本入库、调整 2012 文本的效力标注（见已确认 1）。线上库中已有的错误记录需在部署后重新抓取并经面板导入更正（见已确认 3）。

## #31 删除单行公开法规

新增 `chinalaw law delete <id> [--dry-run]`，与 `norm delete` 对称：

- 只接受精确 id，不按名称或别名解析，避免误删。
- 先检查引用：`article_commentaries`、`norm_pack_items`、`law_relations`（双向）、`applicability_rules`（主 / 备选）。存在引用即拒绝并列出引用，退出码 1。
- 单事务内先删检索索引（`articles_fts`、`laws_fts` 及映射行）和无外键的 `document_number_index` 行，再删 `laws` 主行，由外键级联清理 `articles`、`revisions`、`law_categories`、`law_alias_index`。
- 返回各表删除计数；`--dry-run` 只报告不删除。无交互确认，与 `norm delete` 先例一致。
- 同步更新 `schema` 输出的 CLI 契约、CONTRACT 文档与 CHANGELOG。

**不做**：管理面板删除端点；删除后保留旧 id 到保留行的重定向。
