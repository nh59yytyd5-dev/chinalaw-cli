# 真实用户检索体验与 DeepSeek Harness 验证

## 样本与边界

2026-10-05 通过服务器 SQLite 只读连接提取日志；只取凭据名称为人名的两组调用，
共 193 条，均为 MCP。参与者 01 有 3 条（2026-09-30），参与者 02 有 190 条
（2026-10-02 至 10-03）。排除 agents-readonly、ds、版本验收和并发压测凭据。
原始日志、姓名映射及脱敏逐次轨迹仅保存在被 Git 忽略的本地目录，公开报告不含姓名。

这是工具调用记录，不是完整用户对话、最终回答或满意度调查。83 次成功读条不证明
模型引用正确；重复读取可能是不同任务，日志没有会话 ID，不能直接算用户重复操作率。
时延仅为服务端执行时间，不含网络、模型推理和用户等待；样本集中在一位使用者，
不能推广为全部用户的成功率。

## 需要改善的环节

1. **公开资料和私域资料的工具语义不够清楚。** 五次拒绝集中于把司法解释、虚假诉讼、
   洗钱等公开主题放入 kind=norm。保留权限检查，明确 law/article 是公开资料、norm
   是私人导入的制度/合同等资料；错误回复应给出下一步，而不只是 403。
2. **零命中只给通用短句。** 多个关键词要求在同一条出现；长问题、条号混关键词、
   标题混文号会落空。应该解释本次检索约束、给出可执行的缩短/分拆建议，同时保留
   原来的范围和筛选条件，不能暗中改搜全库或把近似结果当精确结果。
3. **标题子串命中容易被当成同名文件。** “中华人民共和国人民法院法庭规则”两次经
   like_fallback 指向“关于修改……的决定”。先提示核对 official_title 和文件性质，
   不擅自将修改决定等同于完整现行文本，不在本任务中改变法律分类。
4. **全文分页缺少明确续读位置。** 重复 offset=0 现象不直接证明故障，但可以增加
   returned/next_offset，并在工具说明明确 limit 按条目数计算、has_more=false 即已读完。
5. **日志不足以衡量后续改进。** 当前只留命中数，无法区分精确/近似命中、范围未解析、
   分页是否重复；可补充不含正文的诊断摘要，保持不收集密钥与条文全文。
6. **资料覆盖是独立问题。** “量刑指导意见”“审查逮捕证据参考标准”和案例名称的零命中
   不能一概认定为搜索算法缺陷；先核对当前库，保留覆盖缺口，不编造或自动导入未核资料。

## Docker 与模型验证（进行中）

使用独立 Colima profile `chinalaw-eval`，容器 2 CPU/2 GiB，非 root、只读根文件系统、
drop ALL capabilities、no-new-privileges；不挂载 Docker socket、用户 HOME、生产认证库
或原始用户日志。只读挂载代码和公开库，在容器内复制数据库并签发一次性公开 MCP 凭据。

模型由真正的 `@deepseek-ai/dsh` headless profile 调用，接入隔离服务的 Streamable HTTP
MCP。关闭额外遥测和本轮无关工具，只向 DeepSeek 提供检索任务与公开工具返回。
DeepSeek API key 来自本机 Harness，单独只读 secret 挂载，不写入镜像、命令行或报告。
启动余额为 CNY 12.78；每轮记录前后余额、模型、退出状态、完整会话与服务查询日志。
网络/权限/模型错误与余额耗尽分别记录；只有余额不可用或实际余额错误才能认定耗尽。

本文件会继续补充实测修复与余额终态。

## Harness 结果裁剪造成的伪数据缺陷（重要）

真实 DSH 基线 long-queries 任务把“刑法修正案（九）”报告为与“（十一）”混杂。
逐层核验发现：生产快照与 chinalaw 服务完整响应中的两个对象均正确；DSH 的 spill
策略却对超长 JSON 进行头尾拼接，保留了（九）的 title/id 和（十一）的 text/source_url。
模型收到的 JSON 主体恰好仍可解析，后面附有 Omitted 61704 bytes 提示。该项是客户端
输出裁剪引入的假象，未据此修改资料库。

隔离测试 profile 随后关闭 spill-policy 和 tool-result-pruner，保留正常上下文压缩；
后续输出以 profile-facts.json 记录配置。此前配对任务保留原配置以便追溯，不能把跨配置
任务当作严格的时延/费用对照。最终验收应使用完整返回的 profile。

Harness 安装细节：npm 的 dsh rc.6/rc.8 搭配新版 HMR 会启动失败，未成功调用模型的轮次
单独标记为环境失败。实际可运行组合为 dsh 0.1.0-rc.8 + 本机同版 HMR 1.0.16 / loader
1.0.2，并以 Node --expose-internals 启动。没有修改 Harness 的模型循环或调用结果。
API 余额结算有延迟，每轮前后余额不等于该轮准确账单，最终费用以账户余额差为准。

## 最终边界修复与核验

在 v3 的反例任务中，模型报告“120条之一引文识别失败”。复核参数后发现不是数字转换错误，
而是同时传入 in_laws 时旧路径跳过了引文快捷定位。最终版允许范围内引文定位，并再次验证
法规 ID、level/status/region；冲突范围或未解析范围不会越界返回。增设条文、冲突范围与
未知范围回归通过；最终全量 1083 passed、32 skipped、1739 subtests。

已完成的大响应复核在关闭裁剪后未再出现来源拼接：模型用准确 ID 独立读取修正案（九）、
（十一），search/document 对应一致。原先抄错的修正案（十一）ID 换成真实返回值后可正常读取。
最终统计会继续记录截止余额耗尽的所有完成/中断任务。
