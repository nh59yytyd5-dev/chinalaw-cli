## 备份与回滚

发布目录 `/srv/chinalaw/releases/20261028-v0.7.4/`，含 wheel、manifest、预检与演练脚本及其输出、
部署脚本、`database-changes.json`（别名索引变化明细，含新增的 36 行）与 deployment.json。
`backup/` 为 root-only，含 `venv.tar.gz`、SQLite backup API 生成的 `library.db`（init 前）、
`server-state`、服务与代理配置、数据/认证校验值，以及 `site-current.txt`（v0.7.3）。

部署脚本的回滚分两段。新服务启动前失败：恢复旧 venv 与介绍页，并用备份恢复资料库（停服期间只有
init 写过库，恢复后逐表校验）。新服务启动后失败：只恢复 venv 与介绍页，资料库保留，因为新服务可能
已有写入；0.7.3 不认 `alias_rules_version`，照常读取重建后的别名索引。这次未触发回滚。

事后手动回退：停服务、另存现场、恢复旧 venv、校正 `venv/bin` 的 SELinux 标签、把介绍页 `current`
指回 `v0.7.3`，再启动并验证。数据库与认证状态保留上线后的写入，不要盲目用备份覆盖。

演练用的线上库副本（`/var/tmp/chinalaw-dryrun-0.7.4`）与临时分发目录已在验证后删除，所需文件
均已留在发布目录。
