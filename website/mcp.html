02 · 本地 stdio MCP

先从公开数据页安装 CLI、下载并解压 SQLite 包。在支持 mcpServers 的客户端中添加配置，替换为你机器上的绝对路径：

{
  "mcpServers": {
    "chinalaw": {
      "command": "/absolute/path/to/chinalaw-mcp",
      "args": ["--db", "/absolute/path/to/library.db"]
    }
  }
}

chinalaw-mcp 随 CLI 安装。请根据客户端的 MCP 设置格式填写 command 与 args；若客户端找不到 PATH，使用可执行文件绝对路径。默认不向 stdio MCP 暴露私域规范。

03 · 托管 HTTP MCP

本站不提供公开共享令牌，也不开放匿名检索。在 GitHub 说明用途与预计频率，维护者按容量发放独立、可撤销的公开库只读凭据。令牌不要发在公开 Issue 中。

传输协议Streamable HTTP
服务地址https://law.newcombmath.com/mcp
HTTP 请求头Authorization: Bearer YOUR_PERSONAL_TOKEN
权限chinalaw:public:read，无导入、修改、私域读取权限

支持 URL 与请求头配置的客户端，可将以下字段填写到该客户端的远程 MCP 设置中。外层配置格式以客户端文档为准：

{
  "url": "https://law.newcombmath.com/mcp",
  "headers": {
    "Authorization": "Bearer YOUR_PERSONAL_TOKEN"
  }
}

支持环境变量的客户端优先从环境变量读取密钥。示例中的占位符不能直接使用；不要复制他人的令牌。OAuth 所有者授权适用于你自己的服务管理，不是本站的匿名注册入口。

用 curl 检查协议连接

先在终端设置 CHINALAW_TOKEN。此请求只初始化会话，不检索正文；按响应中的会话信息继续使用 MCP 客户端。

curl -i https://law.newcombmath.com/mcp \
  -H "Authorization: Bearer $CHINALAW_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"connection-check","version":"1.0"}}}'

04 · 自托管服务

下载 wheel 后安装 server 可选组件，用自己的数据库启动浏览器面板：

python -m pip install './chinalaw-0.7.0-py3-none-any.whl[server]'
chinalaw-server init --db ./public-library.db
# 如使用 JSON 包，再将 laws/ 导入该库
chinalaw --db ./public-library.db sync --from-dir ./chinalaw-public-2026-09-26-json/laws
chinalaw-server serve --db ./public-library.db --open

以上是本机模式。部署公网需要 HTTPS、所有者密码、反向代理与独立令牌；不要直接把本机配对模式暴露到公网。管理界面的“连接与备份”可创建、撤销令牌，给外部使用者只勾选公开库权限。

05 · 工具与调用流程

工具用途
chinalaw_resolve校验法规名；失败时给候选，不自动采用
chinalaw_article按法规与条号取原文，可传 as_of
chinalaw_search补查原文片段；支持日期、效力、层级等过滤，近似结果有标记
chinalaw_list浏览公开资料目录
chinalaw_document按页读取法规条文；has_more 为真时继续翻页
chinalaw_applicable读取本库已有的时间效力规则线索；覆盖以返回结果为准，不是完整法律意见
  1. 模型已有候选法规和条号时，直接取条；名称不确定时先 resolve。
  2. 核对正文是否对题、版本日期、效力与来源。条号命中不代表记忆准确。
  3. 没有线索、记忆不符或需要配套解释时，再 search；最终引用用 article 核验。
  4. 事实发生在过去时传入 as_of: "YYYY-MM-DD"，并阅读缺失日期提示。
示例：旧记忆中的《仲裁法》第16条，在现行版本中已是机构变更登记。应根据返回正文发现不符，再定位仲裁协议条文；不能仅因工具返回成功就引用。

06 · 初始容量策略与隐私

本站为共享的小规模托管服务，不提供可用性承诺。批量研究与生产集成优先下载数据自托管。

  • 客户端建议最多 2 个并发查询。入口按令牌 限速 5 请求/秒，允许短时突发 20；全站同时处理的查询请求上限为 8。初始化请求也会计入。
  • 遇到 HTTP 429，请按 Retry-After 等待后重试，避免无限重试。访问密钥可到期、撤销或暂停。
  • 托管查询记录时间、工具、查询参数、命中概况与耗时，不记录返回正文。请用法规名、条号和必要关键词查询，不提交可识别的案件隐私。
  • 数据下载由 GitHub Release 承载；网站静态文件不触发数据库查询。数据开放不等于托管计算资源无限开放。

07 · 常见问题

为什么收到 401？

未携带令牌、令牌过期、已撤销或资源地址不匹配。检查请求头和 /mcp 地址；不要尝试共享其他人的密钥。

为什么有的查询没有结果？

库可能没有资料，或使用的说法未出现在法条中。先用已有候选条号取条，必要时换原文片段检索。服务不会自动联网抓取缺失内容。

可以把全部数据从 MCP 翻页下载吗？

完整快照请直接使用公开数据下载包。托管 MCP 用于少量定位与核验，批量翻页会受限流约束。

下载包与线上数量为什么不同？

线上保留了旧 ID 兼容记录和历史工作库内容。公开包从审查后的全国数据独立构建，减少重复；均须核对版本与来源。
